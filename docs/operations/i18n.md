# Internationalisation

**Status:** defect D-017. Persian strings are hard-coded inside server prompts
(`server.ts:725` "یک فایل زیرنویس استاندارد SRT تولید کن", `server.ts:882` "لطفاً برای ویدیوی
زیر زیرنویس تولید کن") and across the UI, while `src/i18n/` exists and is used elsewhere.

---

## 1. Policy

| Rule | Statement |
|---|---|
| I-1 | No user-visible string is hard-coded in a component, service or server prompt. Every string lives in `src/i18n/` under a namespaced key. |
| I-2 | Error messages are keyed by `ErrorCode` (see [../contracts/errors.md](../contracts/errors.md)), not written inline. |
| I-3 | **Server prompts are not UI strings.** They are templates in `server/prompts/`, written in the language the model is expected to answer in, and parameterised by the project's language setting. |
| I-4 | Log messages are **English only**, machine-oriented, with codes — never localised. |
| I-5 | `dir` (`rtl`/`ltr`) is set once at the document root from the active locale; components must not hard-code direction. |
| I-6 | Dates, numbers and timecodes are formatted via `Intl`, not string concatenation. |

## 2. Current state

| Area | Strings | Status |
|---|---|---|
| UI labels | `src/i18n/` exists and is used in several panels | partial ✔ |
| Toasts / errors | hard-coded, often Persian | ✘ |
| Server AI prompts | hard-coded Persian (`server.ts:725`, `:882`) | ✘ — also means the product silently generates Persian content for English users |
| Accessibility labels | no `aria-label` / `lang` audit | ✘ |

## 3. Target

1. Extract every user-visible literal into `src/i18n/messages.<locale>.ts` with dot-namespaced
   keys (`export.error.mediaMissing`).
2. A lint rule bans JSX text nodes and string literals passed to `toast()`/`alert()`; allowed
   forms are `t('key')` and `t('key', params)`.
3. Server prompt templates move to `server/prompts/`; the target language is an explicit
   parameter with a documented default, not an accident of the author's locale.
4. `lang` is set on `<html>`; `dir` follows the locale.
5. Verification: a static test greps for Persian/Arabic script outside `src/i18n/**` and
   `server/prompts/**` and fails on any match.

## 4. Scope note

WP-12 performs the mechanical extraction. Prompt localisation is **not** a rewrite of prompt
content — the current Persian prompt text is preserved as the `fa` template and an `en`
template is added; the default becomes the project's language setting.
