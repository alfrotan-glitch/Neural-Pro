# WP-06 — Behavioural Test Architecture

**Priority:** P1
**Depends on:** WP-00
**Blocks:** WP-10
**Concurrent-safe with:** most WPs (it mostly adds tests)
**Estimated risk:** Medium

---

## 1. Objective

Replace a suite that cannot fail for behavioural reasons with one that can. Closes **D-011**,
unblocks **R-029**.

**Evidence:** 191 files under `tests/`; **0** files require anything from `src/`; 177 are
`fs.readFileSync(...).includes('someString')` assertions. Two suites read
`src/features/video-studio/export/utils/webcodecs-export.ts`, a path that is not the executed
module (`webcodecsExport.ts` under `services/`). `npm test` exits 0 and proves nothing.

## 2. Scope

1. **Taxonomy and enforcement**: `tests/{unit,integration,static,browser,property}`;
   `tests/composition.test.js` fails if a grep-only file sits outside `tests/static/`.
2. **Reproductions promoted**: each `audit/repro-*.{mts,cjs}` is imported by a named test in
   `tests/integration/defects/`, so a regression fails the suite (not just a script).
3. **Defect coverage matrix**: every defect ID in `AUDIT_REPORT.md` maps to at least one
   behavioural test. Where a defect's owning WP has not landed, the test exists and is marked
   `xfail` with the WP id — **never** skipped silently, and never deleted.
4. **Parity harness**: semantic (L1) property tests; pixel (L2) Playwright + `pixelmatch`
   suite with **declared** tolerances (0.5 % differing pixels, no pixel above ΔE 32).
5. **Browser suite**: real export in Chromium, headless-export test, memory-growth test
   (50 iterations), interaction smoke (import → edit → save → reload → export).
6. **Fixtures**: synthetic deterministic media committed locally; **no test may require
   network media**.
7. **Coverage**: ≥ 80 % line coverage of `src/domain/**` (diagnostic elsewhere).
8. **Flake policy**: quarantine with an issue, never delete; no wall-clock sleeps for
   synchronisation (inject a clock).

## 3. Allowed files

```
tests/**
playwright.config.ts, vitest.config.ts
package.json                      (scripts + devDependencies only)
docs/testing/**, docs/quality/release-gates.md, docs/execution/verification-matrix.md
```

## 4. Prohibited files

```
src/**                            (WP-06 does not change production behaviour)
server.ts
audit/repro-*                     (imported, not modified)
docs/contracts/**
```

**Exception:** if a test cannot be written without a production seam (e.g. injecting a clock),
the change is a one-line dependency-injection addition, made in a **separate commit** naming the
WP that owns the file, with that WP owner's review.

## 10. Acceptance criteria

1. `npm test` runs ≥ 1 behavioural test per defect ID that has an owning WP merged.
2. `tests/composition.test.js` fails when a grep-only file is added to `tests/unit/`.
3. Each of the six reproductions is imported by a named test; a deliberate regression in the
   production module fails that test.
4. The browser suite runs and produces a report whose `cases` > 0.
5. No test depends on network media or on `ffmpeg`.
6. Pixel-parity tolerances are declared in one file, not per-run.

## 12. Merge strategy

Continuous — merge test additions as they are written. Rebase frequently; it does not own
production files.

## 13. Conflict risks

| Risk | Mitigation |
|---|---|
| Tests written against a module that another WP is rewriting | mark the test `xfail(wp-XX)` rather than racing the rewriter |
| Browser suite is flaky | quarantine with an issue; never delete; require a root cause before re-enabling |
| Pixel tolerance tuning hides real drift | tolerances live in one file; any change requires a review note and a defect report |
