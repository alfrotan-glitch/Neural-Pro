# WP-09 — AI Hardening

**Priority:** P1
**Depends on:** WP-01
**Blocks:** WP-10 (Stage E)
**Concurrent-safe with:** WP-07
**Estimated risk:** Medium

---

## 1. Objective

Make AI integration typed, validated, bounded and honest (ADR-005, ADR-008, ADR-009).
Closes **D-009**, **D-022**; addresses **T-04**, **R-004**, **R-023**.

**Evidence (D-009):**
```ts
// server.ts:216   if (!apiKey)  return res.json(simulated);
// server.ts:236   catch (e)     return res.json(simulated);
// generateSimulatedContent → canned croissant dialogue |
//                            Buffer.alloc(44 + 24000 * 2)  // exactly 1.00 s of silence
```
`/api/generateContent` sets **no** `fallback`/`degraded` marker; `App.tsx` never checks for one
and shows a **hard-coded** green "API Connected" badge. Every failure — missing key, quota,
invalid key, safety block, network — is indistinguishable from success.

**Evidence (D-022):** `DEFAULT_CAPTION_FPS = 30`; `server.ts` call sites at 883, 919, 970, 1010
pass no fps ⇒ wrong `HH:MM:SS:FF` for 24/60 fps projects.

**Evidence (WAV):** `App.tsx:240 createWavUrlFromBytes(bytes, sampleRate = 24000)` writes a
44-byte header assuming 24 kHz / mono / 16-bit with no validation against the response.

## 2. Scope

1. **Client `AiGateway`** replacing the fake SDK (`App.tsx:8-21`): `script()`, `speech()`,
   `health()`; operation inputs only.
2. **Migrate call sites**: podcast generation and TTS in `App.tsx` → `/api/ai/script` and
   `/api/ai/speech`.
3. **No fabricated success**: every failure path yields a typed `AppError` and a visible
   message; the connection badge reads `/api/health/ai`.
4. **TTS validation**: declared `sampleRate`/`channels` checked against the allowed set; decode
   with `decodeAudioData`; cross-check `durationSeconds` (tolerance 250 ms); build the WAV header
   **from the decoded buffer**; reject all-zero (silent) audio.
5. **Prompt boundary**: server templates with `<<<USER_INPUT>>>` delimiters + an injection
   regression test.
6. **Retry/timeout**: move the inline TTS retry loop into the workflow policy (bounded 3,
   exponential with jitter); server-side `AbortSignal.timeout`.
7. **Caption FPS**: `projectFps` sent on every caption request; `DEFAULT_CAPTION_FPS` deleted
   (`SHIM-005` deprecated alias, removed in WP-12).
8. **Degraded mode**: only with `AI_ALLOW_SIMULATION=true` **and** `source:'simulated'` markers
   **and** a persistent UI banner. Default off.
9. **Remove `VITE_MOCK_TTS`** (undocumented env var) or document it and make it explicit.

## Runtime reconciliation (2026-09-09)

| Item | Change |
|---|---|
| Rationale restated | The operation allowlist is now justified by the **AI Studio server-side secret model**, not only by generic security hygiene: `GEMINI_API_KEY` is injected server-side, and **sharing an app bills the owner's key**, so an unauthenticated passthrough is a cost incident as well as a security one |
| Scope addition | Every AI operation must be **bounded**: explicit timeout, bounded retry, bounded payload. Long-running or background server work is not guaranteed by the AI Studio runtime (AS-INV-11) |
| Unchanged | No fake success (AS-INV-07); the path remains `client intent → validated operation → server-owned configuration → Gemini` |
