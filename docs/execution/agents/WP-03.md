**Evidence:**

       scaleX=200 scaleY=100 rot=45 → drift 662.019 px
       scaleX=150 scaleY=90  rot=15 → drift 145.389 px

       CanvasExportRenderer receives renderSnapshot === undefined and recomputes.

## 2. Scope

1. **`getCanonicalTransformMatrix(transform, w, h): DOMMatrix`** — one definition,
   `T(origin+x, origin+y) · R(rotation) · S(scale·scaleX, scale·scaleY)`.
2. **Derive `getPreviewTransformCss` from that matrix** — preview may not hand-write a transform
   string.
3. **Add `clipPath` + shared corner-radius constant** to the render model; apply `ctx.clip()`
   (with `roundRect`, falling back to `rect`) in the video/image branch of
   `CanvasExportRenderer`; apply `overflow:hidden` + `border-radius` from the same constant in
   `VideoPlayer`.
4. **Thread the `renderSnapshot`** from the compositor index into export, so the atomic snapshot
   — and therefore the diagnostics gate — is actually used. Then **decide by measurement**
   whether the diagnostics subsystem earns its place: if the canonical plan makes it redundant,
   delete it under WP-12; if it catches real drift, wire it into CI. Record the decision and the
   evidence either way.
5. **`RenderFpsAuthority`** — one fps threaded into frame count, encoder config, frame
   timestamps and caption timecodes (D-020).
6. **Caption layer** becomes `CanonicalRenderLayer { kind:'text' }` rendered from the same plan
   in both targets.
7. **Shared constants:** `MEDIA_FRAME_SIZE_PERCENT = 85` used by both sides (currently a CSS
   literal in two places in `VideoPlayer.tsx`).
