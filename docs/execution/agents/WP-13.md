# WP-13 — AI Studio Runtime Verification

**Priority:** P1 (it de-risks WP-02, WP-05, WP-06 and WP-10)
**Depends on:** WP-00 (probe harness + report format), WP-07 (`/api/runtime/capabilities`)
**Blocks:** the **RUNTIME CERTIFIED** claim and gate **G-31**
**Concurrent-safe with:** every other WP except where it needs a server route (via WP-07)
**Estimated risk:** Medium (it depends on access to a live AI Studio environment)

---

## 1. Objective

Resolve the twelve **RUNTIME-UNKNOWN** capability items and the six frame-specific unknowns
(`P-01…P-06`) **by execution inside Google AI Studio**, and produce the AI Studio compatibility
gate evidence (G-31 / AS-01…AS-16) for **both** contexts: the preview frame and a published app
URL.

Until this WP runs, no statement about AI Studio compatibility is evidence — it is reasoning,
and the architecture forbids converting uncertainty into assumption (ADR-000).

## 2. Context

The application **is** an AI Studio app:

* `metadata.json` — app manifest with `majorCapabilities: ["MAJOR_CAPABILITY_SERVER_SIDE_GEMINI_API"]`
  and `requestFramePermissions: []`;
* `README.md` — "View your app in AI Studio: https://ai.studio/apps/bdf5ad65-6c0d-48f4-8ba5-1e1a337f20ce";
* `.env.example` — AI Studio-injected `GEMINI_API_KEY` and `APP_URL`;
* `vite.config.ts` — `DISABLE_HMR`, `allowedHosts` for the proxied host.

The previous blueprint never inspected these and treated the publish path (Cloud Run) as the
target. This WP produces the missing runtime evidence.

## 3. Scope

1. **Run the capability probe** (`GET /api/runtime/capabilities` + the in-browser probe) in both
   contexts; record the `CapabilityReport[]`.
2. **Resolve `P-01…P-06`** (see
   [../../architecture/AI-STUDIO-MEDIA-RUNTIME.md](../../architecture/AI-STUDIO-MEDIA-RUNTIME.md) §2.2):
   * `P-01` downloads permitted inside the frame (decisive for export delivery);
   * `P-02` storage partitioning / availability;
   * `P-03` WebCodecs / `OfflineAudioContext` availability and throttling;
   * `P-04` CSP restrictions;
   * `P-05` proxy behaviour for long requests and aborts;
   * `P-06` dev-container vs published-app differences.
3. **Execute G-31 / AS-01…AS-16** per
   [../../quality/AI-STUDIO-COMPATIBILITY-GATE.md](../../quality/AI-STUDIO-COMPATIBILITY-GATE.md);
   record per-criterion evidence in both contexts.
4. **Update the classification table**: move each `C` item to `A`, `B` or `D` with evidence.
   Items that remain unresolved stay `C` with a named owner — never silently promoted.
5. **Feed findings back**: if `P-01` fails, WP-04's delivery fallbacks become mandatory (they
   are already specified). If `P-02` fails, WP-05 must make project export/import the primary
   durability mechanism. If `P-06` shows material differences, both contexts are certified
   separately thereafter.
6. **Do not fix product defects here.** This WP observes and records; defects go to their owning
   WP with evidence attached.

## 9. Procedure (executable, ordered)

1. Open the app in **Build mode**. Record the app id and the container/dev notice.
2. `GET /api/runtime/capabilities` → save JSON.
3. Run the in-browser probe: `MediaRuntimeCapabilities` → save JSON.
4. **AS-01** boot: screenshot + console (assert zero uncaught errors).
5. **AS-02** boundary: call health + health/ai; save responses.
6. **AS-05/06** media: import a local MP3 + MP4 + PNG; record measured durations.
7. **AS-07** timeline: add/trim/move; undo/redo; assert `totalDuration`.
8. **AS-08** persistence: save → **reload** → assert media resolves (this resolves `P-02`).
9. **AS-09/AS-15** export: export the fixture; assert the file lands on disk
   (this resolves `P-01`); hash the artefact; probe its frame count/duration.
10. **AS-10** export with the Preview panel closed.
11. **AS-11** cancellation: cancel at each of the 8 steps; assert terminal state + resources.
12. **AS-12** failures: induce the five failure modes; assert typed non-success and honest UI.
13. **AS-13** no native binary: static grep + observe no server export traffic.
14. **AS-14** independence: repeat the flow with no external service involvement.
15. **AS-16** capability detection: disable/deny a capability and assert the honest refusal.
16. **Publish** the app. Repeat 2–15 against the published URL (context U).
17. Repeat the export timing measurement in both contexts to characterise `P-06`.
